# JSON report schema

The validator emits a single JSON document with a `reports` wrapper holding two sibling
report trees (`PDF/UA` and `WCAG`) plus document-level metadata. Key order is pinned via
Jackson `@JsonPropertyOrder` on every DTO — preserve it for downstream consumers.

Generated by `PDFValidator` → `ReportBuilder.build(...)` + `WCAGReportBuilder.build(...)`,
serialized by `ReportWriter`.

## Tree

```
{root}                                                                ReportDTO
└── reports                                                           ReportsDTO
    ├── document                  string                              path passed on CLI
    ├── info                                                          DocumentInfoDTO
    │   ├── title                 string                              XMP dc:title → Info /Title → "(no title)"
    │   ├── filename              string
    │   ├── language              string                              Catalog /Lang via LangUtils → "(no language)" if missing or read fails
    │   ├── pages                 int
    │   ├── tags                  int                                 count of struct elements
    │   ├── sizeBytes             long
    │   ├── size                  string                              "1.2 MB" (locale-stable)
    │   └── compliant             boolean                             true iff PDF/UA.summary.failed == 0
    │
    ├── PDF/UA                                                        PdfUaSectionDTO
    │   ├── shortSummary[]                                            ShortSummaryEntryDTO (PAC 11-row header)
    │   │   ├── name              string                              sub-category label
    │   │   ├── status            enum                                FAILED|WARNING|PASSED|NOT_APPLICABLE|NOT_IMPLEMENTED
    │   │   └── counts            CountsDTO
    │   └── categories[]                                              CategoryDTO
    │       ├── name              string                              e.g. "Basic requirements"
    │       ├── status            enum
    │       ├── counts            CountsDTO
    │       └── subCategories[]                                       SubCategoryDTO
    │           ├── name          string                              e.g. "Content"
    │           ├── status        enum
    │           ├── counts        CountsDTO
    │           └── checkpoints[]                                     CheckpointReportDTO
    │               ├── element       string                          leaf label OR container name (e.g. "Optional Content", "Annotations")
    │               ├── status        enum
    │               ├── counts        CountsDTO
    │               ├── errorMessage  string  (optional)              leaf-only; fallback message for findings
    │               ├── findings[]    (optional)                      leaf-only; FindingEntryDTO
    │               │   ├── message   string  (nullable)
    │               │   ├── severity  enum                            ERROR|WARNING|PASSED
    │               │   ├── page      int     (nullable, omitted when null/0)
    │               │   └── bBox      BBoxDTO (nullable)               PDF user-space (origin bottom-left); fields emitted in declaration order
    │               │       ├── top    float                          y-coordinate of the top edge
    │               │       ├── left   float                          x-coordinate of the left edge
    │               │       ├── height float
    │               │       └── width  float
    │               └── checkpoints[] (optional)                      container-only; child CheckpointReportDTO nodes (same shape, recursive)
    │
    └── WCAG                                                          WCAGReportDTO
        ├── name                  string                              "WCAG 2.2"
        ├── status                enum
        ├── counts                CountsDTO
        └── principles[]                                              PrincipleDTO    (1 Perceivable, 2 Operable, 3 Understandable, 4 Robust)
            ├── name              string
            ├── status            enum
            ├── counts            CountsDTO
            └── guidelines[]                                          GuidelineDTO    (1.1, 1.2, …, 4.1)
                ├── name          string
                ├── status        enum
                ├── counts        CountsDTO
                └── criteria[]                                        CriterionDTO    (1.1.1, 1.3.1, …)
                    ├── name      string                              e.g. "1.3.1 Info and Relationships"
                    ├── status    enum
                    ├── counts    CountsDTO
                    ├── findings[]    (optional)                      FindingEntryDTO  ← present when criterion IS the leaf (e.g. 1.2.1, 3.1.1)
                    └── leaves[]      (optional)                      WCAGLeafDTO      ← present when criterion has named sub-leaves
                        ├── name      string                          PAC-canonical leaf label
                        ├── status    enum
                        ├── counts    CountsDTO
                        └── findings[] (optional)                     FindingEntryDTO
```

## Notes

- **`checkpoints[]` is unified** — every entry under a sub-category (or under a container)
  is a `CheckpointReportDTO`. Two shapes:
  - **Leaf** — has `findings[]` (or is empty when the status is `NOT_APPLICABLE` /
    `NOT_IMPLEMENTED`), no nested `checkpoints[]`.
  - **Container** — has nested `checkpoints[]`, no `findings[]`. Its `element` holds the
    container name (e.g. `"Optional Content"`, `"Annotations"`). Currently exactly one
    level deep (containers don't nest further), but the shape is recursive.

  The 4th level is set on `PDFUACheckpoint` via the `group` constructor argument; absent
  → the checkpoint is a direct leaf under the sub-category.
- **`findings` vs `leaves` on `CriterionDTO`** — exactly one is populated. If the
  `WCAGCriterion` constant has `leaf == null`, the criterion *is* the leaf — findings
  attach directly. Otherwise the criterion holds one `WCAGLeafDTO` per named child.
- **`counts` rollup** — at every level, `counts` is the sum of its children's `counts`.
  Final leaves count one entry per emitted `FindingDTO` (ERROR/WARNING/PASSED). Leaves
  with status `NOT_APPLICABLE` or `NOT_IMPLEMENTED` have zero counts.
- **Status enum** — five values: `FAILED`, `WARNING`, `PASSED`, `NOT_APPLICABLE`,
  `NOT_IMPLEMENTED`. Rollup precedence: any FAILED → FAILED; else any WARNING → WARNING;
  else any PASSED → PASSED; else any NOT_APPLICABLE → NOT_APPLICABLE; else
  NOT_IMPLEMENTED.
- **`@JsonInclude(NON_EMPTY)`** is set on most container DTOs, so empty arrays and null
  fields are omitted from the JSON.
- **PAC-canonical strings** — every `name` / `element` / criterion label is byte-identical
  to PAC's UI text. Don't reword.
