# JSON report schema

The validator emits **two** JSON files per run:

- `<basename>.simple.json` — hierarchical PAC-shaped tree with `documentInformation`, PDF/UA + WCAG report sections, `uaIndex`, rolled-up counts, and per-node severity.
- `<basename>.detailed.json` — flat, failure-only issue list per report type, with per-instance `(pageIndex, rectangle)` details plus page `cropBoxRanges`.

Both files share a `jobId` UUID generated per run. Key order is pinned via Jackson `@JsonPropertyOrder` on every DTO — preserve it for downstream consumers, PAC's export enforces the same order.

Generated by `com.netralabs.report.pac.{SimpleReportBuilder, DetailedReportBuilder}`, serialized by `PacReportWriter`.

The pre-PAC combined report (`<basename>.report.json`) is still available behind a `--legacy` CLI flag / service parameter — see [Legacy shape](#legacy-shape) at the bottom.

## simple.json

```
{root}                                                                SimpleReportDTO
├── body                                                              SimpleBodyDTO
│   ├── jobId                    string                               UUID; matches detailed.json
│   ├── name                     string                               source PDF basename (no extension)
│   ├── documentInformation                                           DocumentInformationDTO
│   │   ├── pageCount            int
│   │   ├── title                string (nullable)                    XMP dc:title → Info /Title → null
│   │   ├── subject              string (nullable)
│   │   ├── author               string                               "" if absent
│   │   ├── keywords             string (nullable)
│   │   ├── creationDate         string (nullable)                    ISO 8601 — converted from PDF D:YYYYMMDD... format
│   │   ├── modificationDate     string (nullable)                    ISO 8601
│   │   ├── creator              string (nullable)
│   │   ├── producer             string (nullable)
│   │   ├── language             string (nullable)                    Catalog /Lang (or null)
│   │   ├── ids                  string (nullable)                    "/ID" array, hex-joined with ", "
│   │   ├── isTagged             bool                                 catalog /MarkInfo /Marked && /StructTreeRoot present
│   │   ├── reportLanguage       string                               "en"
│   │   ├── numberOfTags         int                                  count of struct elements
│   │   └── sizeInKb             long                                 source file size in KB (rounded)
│   ├── reports[]                                                     ReportSectionDTO
│   │   ├── type                 string                               "PDF/UA" or "WCAG2CheckSet"
│   │   ├── uaIndex              double (PDF/UA only)                 100 - (100*E + 5*W) * 100 / (P+E+W), clamped [0,100]
│   │   └── report                                                    NodeDTO (recursive)
│   │       ├── value                                                 NodeValueDTO
│   │       │   ├── checkId              string                       PAC-canonical (see PacCheckId)
│   │       │   ├── caption              string                       PAC-canonical human label
│   │       │   ├── terminationCount     int
│   │       │   ├── errorCount           int
│   │       │   ├── warningCount         int
│   │       │   ├── passedCount          int
│   │       │   ├── severity             string                       "Error" | "Warning" | "Passed" | "Skipped"
│   │       │   └── severityId           int                          0 | 1 | 2 | 3
│   │       ├── children[]     (optional)                             NodeDTO
│   │       └── issues[]       (optional)                             IssueSummaryDTO (present on failing leaves)
│   │           ├── issueId              string                       PAC-canonical or synthetic "<checkId>-Issue"
│   │           ├── severity             string
│   │           ├── severityId           int
│   │           ├── caption              string
│   │           └── count                int
│   └── creationDate             string                               ISO 8601, UTC
└── version                                                           VersionDTO
    ├── major                    int                                  2
    └── minor                    int                                  0
```

### Notes

- **`type` uses the checkId, not the display name.** PDF/UA is literally `"PDF/UA"`; WCAG is `"WCAG2CheckSet"` (its root checkId), matching PAC's export.
- **`uaIndex` is PDF/UA-only.** Serialised via `@JsonInclude(NON_NULL)`, so the WCAG section omits it entirely.
- **`children` vs `issues`** — a branch node has `children`, a failing leaf has `issues`. Passing / skipped leaves have neither and drop the empty arrays via `@JsonInclude(NON_EMPTY)`.
- **Severity vocabulary** is fixed: `Error=0`, `Warning=1`, `Passed=2`, `Skipped=3`. Leaf severity is derived from counts (`errorCount > 0 → Error`, else `warningCount > 0 → Warning`, else `passedCount > 0 → Passed`, else `Skipped`); branch severity rolls up the same precedence (Error > Warning > Passed > Skipped).
- **Counts roll up** — at every level, each count is the sum of that count on all direct children.

## detailed.json

```
{root}                                                                DetailedReportDTO
├── body                                                              DetailedBodyDTO
│   ├── jobId                    string                               UUID; matches simple.json
│   ├── name                     string                               source PDF basename
│   ├── issues[]                                                      DetailedTypeDTO
│   │   ├── type                 string                               "PDF/UA" or "WCAG2CheckSet"
│   │   └── issues[]                                                  DetailedIssueDTO
│   │       ├── issueId          string
│   │       ├── severity         string                               "Error" | "Warning"
│   │       ├── severityId       int
│   │       ├── checkId          string                               PAC-canonical leaf checkId
│   │       ├── caption          string                               PAC-canonical issue caption
│   │       ├── count            int                                  aggregate count
│   │       └── details[]                                             IssueDetailDTO — one entry per instance
│   │           ├── pageIndex    int                                  0-based
│   │           └── rectangle                                         RectangleDTO — PDF user-space (origin bottom-left)
│   │               ├── top      double
│   │               ├── bottom   double
│   │               ├── left     double
│   │               └── right    double
│   ├── cropBoxRanges[]                                               CropBoxRangeDTO — contiguous same-CropBox pages
│   │   ├── startPageIndex       int
│   │   ├── endPageIndex         int
│   │   └── cropBox              RectangleDTO
│   └── creationDate             string                               ISO 8601, UTC
└── version                                                           VersionDTO
```

### Notes

- **Failure-only.** Only checkpoints with `severity ∈ {Error, Warning}` appear; passing checkpoints are omitted.
- **Two type sections.** A checkpoint that maps to both PDF/UA and a WCAG criterion (e.g. `WidgetAnnotationsInFormTag` → both `PDF/UA` and WCAG 4.1.1 Parsing) appears in **both** `issues[]` entries — same `checkId`, same `count`, same `details[]`.
- **`details[]` may be empty** when the underlying rule can't derive a page + bbox for the finding. Aggregate rules like `FigureTag-PossibleInappropriateUseParagraph` intentionally emit `details: []` — PAC follows the same convention.
- **`cropBoxRanges` help viewers map bboxes to pages.** Contiguous pages sharing the same crop box are collapsed into one range so a viewer only stores N ranges instead of N page rects.

### Minimal example

```json
{
  "body": {
    "jobId": "6a9754b2-3fe5-405b-95c0-f71c3d861e23",
    "name": "sample",
    "issues": [
      {
        "type": "PDF/UA",
        "issues": [
          {

            "severity": "Error", "severityId": 0,
            "checkId": "WidgetAnnotationsInFormTag",
            "caption": "\"Widget\" annotation not nested inside a \"Form\" structure element",

              { "pageIndex": 11, "rectangle": { "top": 621.076, "bottom": 611.003, "left": 226.604, "right": 378.132 } }
              /* + 15 more */
            ]
          }
        ]
      }
    ],
    "cropBoxRanges": [
      { "startPageIndex": 0, "endPageIndex": 15, "cropBox": { "top": 841.92, "bottom": 0, "left": 0, "right": 595.32 } }
    ],
    "creationDate": "2026-07-16T06:29:22Z"
  },
  "version": { "major": 2, "minor": 0 }
}
```

## checkId & issueId catalogues

- **`PDFUACheckpoint` leaf checkIds** — every enum constant maps to a PAC-canonical checkId string via `com.netralabs.report.pac.PacCheckId.forLeaf(...)`. Common ones: `PDFParsable`, `StructuralParentTree`, `FontsAreEmbedded`, `ContentIsTaggedOrArtifacted`, `CharactersUnicodeMappable`, `WidgetAnnotationsInFormTag`, `LinkAnnotationsInLinkTag`, `TablesAreRegular`, `FigureHasBBox`, `FigureHasAltText`, `MetadataInCatalogExists`, `DocumentContainsPDFUAIdentification`, `DocumentContainsTitle`, `DisplayDocTitleIsTrue`, `AccessibleEncyptionSettings`, `TextContentHasValidContrast`.
- **Branch checkIds** — hierarchy nodes (categories, subcategories, groups) have their own checkIds. PDF/UA: `PDFUABasicRequirements`, `ISO32000-1`, `PDFUAFont`, `PDFUAContent`, `PDFUAOptionalContent`, `PDFUAEmbeddedFiles`, `PDFUANaturalLanguage`, `PDFUAStructure`, `PDFUAStructureElements`, `PDFUAHeading`, `PDFUANotes`, `PDFUAAnnotations`, `PDFUAFigure`, `PDFUATable`, `PDFUATagging`, `PDFUARoleMap`, `PDFUAAlternativeText`, `PDFUASettingsAndMetadata`, `PDFUAMetadatata` *(PAC's misspelling)*, `PDFUADocumentSettings`. WCAG: `WCAG2CheckSet` → `WCAG2{Perceivable,Operable,Understandable,Robust}CheckSet` → guideline check sets → criterion check sets.
- **`issueId`** — PAC-known codes: `StructuralParentTree-InconsistentEntry`, `WidgetAnnotationsInFormTag-NotUsed`, `LinkAnnotationsInLinkTag-NotUsed`, `TablesAreRegular-IrregularRow`, `FigureTag-PossibleInappropriateUseParagraph`, `TextContentHasValidContrast-NotEnoughContrast`. Other checkpoints synthesise `<checkId>-Issue` with the checkpoint's `errorMessage` (or `element`) as caption.

## Legacy shape

The pre-PAC combined report is available via `--legacy` on the CLI. Wrapped by
`ReportsDTO`:

```
{root}                                                                ReportDTO
└── reports                                                           ReportsDTO
    ├── document                  string                              path passed on CLI
    ├── info                                                          DocumentInfoDTO
    │   ├── title / filename / language / pages / tags / sizeBytes / size / compliant
    ├── PDF/UA                                                        PdfUaSectionDTO
    │   ├── shortSummary[]                                            ShortSummaryEntryDTO (PAC 11-row header)
    │   └── categories[] → subCategories[] → checkpoints[]            CategoryDTO / SubCategoryDTO / CheckpointReportDTO
    ├── WCAG                                                          WCAGReportDTO
    │   └── principles[] → guidelines[] → criteria[] → leaves[]       PrincipleDTO / GuidelineDTO / CriterionDTO / WCAGLeafDTO
    └── quality (optional)                                            QualityReportDTO
```

Legacy status enum: `FAILED | WARNING | PASSED | NOT_APPLICABLE | NOT_IMPLEMENTED`. Rollup precedence: any FAILED → FAILED; else any WARNING → WARNING; else any PASSED → PASSED; else any NOT_APPLICABLE → NOT_APPLICABLE; else NOT_IMPLEMENTED.

Legacy counts uses `{passed, warning, error}` (three ints) at every level.

Legacy property order at each node: `name → status → counts → children/findings`; per-finding: `message → severity → page → bBox` where `bBox` is `{top, left, height, width}` in PDF user-space.

Do not evolve the legacy shape further — new consumers should target the PAC shape above. The legacy code lives in `com.netralabs.report` and is kept for downstream consumers mid-migration.
